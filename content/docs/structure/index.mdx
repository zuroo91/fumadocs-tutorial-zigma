## Prinsip Organisasi

1. **Domain-driven** — Kelompokkan komponen berdasarkan fitur (`auth`, `game`, `shop`),
   bukan berdasarkan jenis (`components`, `containers`).
2. **Co-locate state** — Zustand store untuk fitur besar diletakkan di `store/<feature>.js`
   di samping komponennya.
3. **Service layer** — Semua interaksi Firebase/Socket.io dibungkus di `services/`,
   komponen tidak boleh import Firebase langsung.
4. **Server terpisah** — Game logic yang sensitif (matchmaking, anti-cheat) ditaruh
   di folder `server/` independen agar bisa di-scale terpisah.
