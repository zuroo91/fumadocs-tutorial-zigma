# Database Schema

Zigma menggunakan **Supabase (PostgreSQL)** sebagai pusat data utama. Seluruh pembacaan data soal kuis dan penyimpanan hasil akhir permainan dilakukan secara terstruktur melalui database relasional.

Terdapat dua koneksi Supabase dalam ekosistem Zigma:
1. **Supabase Utama (Main Data Center)**: Menyimpan master data kuis (`quizzes`), profil akun pengguna GameForSmart (`profiles`), dan sesi permainan utama (`game_sessions`).
2. **Supabase B**: Digunakan untuk replikasi sesi live ke platform GameForSmart melalui schema `zigma`.

---

## 1. Tabel: `quizzes`

Menyimpan master data kuis yang dibuat oleh guru, host, atau admin platform GameForSmart.

```sql
CREATE TABLE public.quizzes (
    id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    title VARCHAR(255) NOT NULL,
    category VARCHAR(100) DEFAULT 'umum',
    language VARCHAR(10) DEFAULT 'id',
    description TEXT,
    questions JSONB NOT NULL DEFAULT '[]'::jsonb,
    created_at TIMESTAMPTZ DEFAULT now(),
    updated_at TIMESTAMPTZ DEFAULT now()
);
```

### Struktur Objek JSON `questions`:
Soal-soal kuis disimpan dalam kolom `questions` berbentuk array JSON:

```json
[
  {
    "id": 1,
    "text": "Berapakah hasil dari 15 x 12?",
    "imageUrl": "",
    "answerType": "text",
    "options": ["150", "160", "180", "200"],
    "correctAnswer": 2
  }
]
```

> **Keamanan Kuis**: Server Colyseus membaca array `questions` dari database saat room dibuat, lalu mengekstrak kunci jawaban (`correctAnswer`) ke dalam dictionary privat server (`this.questionCorrectAnswers`). Kunci jawaban **tidak pernah disinkronkan ke client**.

## 2. Tabel: `game_sessions`

Menyimpan status dan riwayat setiap sesi permainan yang dibuat oleh host.

```sql
CREATE TABLE public.game_sessions (
    id VARCHAR(50) PRIMARY KEY, -- XID unik (20-karakter)
    room_code VARCHAR(6) NOT NULL, -- PIN 6-digit (misal: "ABC123")
    host_id VARCHAR(100) NOT NULL,
    quiz_id UUID REFERENCES public.quizzes(id),
    status VARCHAR(20) DEFAULT 'waiting', -- 'waiting' | 'active' | 'finished'
    difficulty VARCHAR(20) DEFAULT 'easy', -- 'easy' | 'medium' | 'hard'
    question_count INT DEFAULT 5,
    timer_seconds INT DEFAULT 300,
    allowed_user_ids JSONB DEFAULT '[]'::jsonb, -- Whitelist peserta untuk sesi kompetisi
    participants JSONB DEFAULT '[]'::jsonb, -- Snapshot hasil & statistik seluruh pemain
    started_at TIMESTAMPTZ,
    finished_at TIMESTAMPTZ,
    created_at TIMESTAMPTZ DEFAULT now()
);
```

### Struktur Objek Partisipan dalam `participants`:
Saat permainan berakhir, endpoint `/api/game/sync-results` mengompilasi snapshot ranking dan performa tiap siswa ke dalam kolom `participants`:


## 3. Tabel: `profiles`

Menyimpan profil identitas pemain yang terdaftar di platform GameForSmart:

```sql
CREATE TABLE public.profiles (
    id VARCHAR(50) PRIMARY KEY,
    auth_user_id UUID REFERENCES auth.users(id) ON DELETE CASCADE,
    username VARCHAR(100) UNIQUE NOT NULL,
    email VARCHAR(255) NOT NULL,
    fullname VARCHAR(255),
    nickname VARCHAR(100),
    avatar_url TEXT,
    language VARCHAR(10) DEFAULT 'id',
    role VARCHAR(50) DEFAULT 'student',
    created_at TIMESTAMPTZ DEFAULT now(),
    updated_at TIMESTAMPTZ DEFAULT now()
);
```

## 4. Keamanan & Hak Akses (RLS & Service Role)

* **Client**: Menggunakan Anon Key Supabase hanya untuk membaca profil akun yang sedang login dan melakukan autentikasi via `@supabase/ssr`.
* **Server**: Menggunakan `SUPABASE_UTAMA_SERVICE_ROLE_KEY` (service role) agar dapat melakukan operasi bypass Row Level Security (RLS) saat menyimpan sesi game, memvalidasi whitelist sesi kompetisi, dan mengambil soal kuis.
